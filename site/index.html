08 / METHOD & DICTIONARY

方法、边界与数据字典

对照的是当前快照中的结构化数据，不是对完整游戏行为的声明。

A

权威数据流

Godot 运行时由 NetworkManager 加载 System.db；本次使用 Zircon 同一 MirDB 模型只读导出 MapInfo、NPCInfo、MovementInfo 与 RespawnInfo。`DataLayer` 的 frame/effect/sound JSON 不是地图主数据。

MUD3 地图定义与有向坐标连接来自 MapInfo.txt；刷怪按 Mongen.txt 的 loadgen 顺序读取 Mon_Def/*.gen；NPC 索引来自 Merchant.txt。网站怪物清单与地图目录仅作辅助，不替代游戏源数据。

B

地图身份

MUD3 方括号首字段 ↔ Godot MapInfo.FileName。仅唯一稳定 ID 匹配；大小写折叠记录为格式差异。地图名、图片、研究快照不建立身份映射。

C

NPC 与怪物名称

Godot 中文名只采用实际 db_names.json zh 翻译；精确唯一时才与 MUD3 名称关联。网站怪物分类只作名称解释，不证明 MUD3 刷新事实。

D

连接与坐标

比较 MUD3 MapInfo.txt 有向地图对与 Godot MovementInfo 的源 / 目标地图 ID。MUD3 坐标点和 Godot Region 结构不同；不计算区域质心、不读取地图格子。

E

空值与去重

源行 / 数据库 Index 逐条保留，不对 NPC、Gen 行或 Movement 去重；重复 load 也保留。只有有向地图对集合计数采用去重口径。false、0、空值和无记录分开呈现。

F

置信度与缺失

置信度描述匹配规则，不表示正确概率。source_missing 只指本次已加载数据的一侧无同键记录；未映射、缺少 Region 或解析异常不能推导游戏里不存在。
